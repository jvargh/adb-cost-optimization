# Human handoff validation gate

The toolkit SHALL NOT be handed to a user based only on unit, contract, mock, or synthetic tests.

Before human handoff, the maintainer must execute every documented front-door command that is applicable to the target environment.

## Mandatory command matrix

| Command | Required validation |
|---|---|
| `Invoke-Assessment.ps1 -Action Validate` | Safety, Pester, and Python suites pass |
| `Invoke-Assessment.ps1 -Action Readiness` | Completes without SQL Warehouse approval or auto-start |
| `Invoke-Assessment.ps1 -Action Readiness -ApproveSqlWarehouseAutoStart` | Real SQL-backed collectors submit successfully, return source statuses, and the Warehouse subsequently autostops |
| `Invoke-Assessment.ps1 -Action Reports` | Recreates the latest report suite without recollecting |
| `Invoke-Assessment.ps1 -Action Open` | Opens or resolves the latest report index |
| `Invoke-Assessment.ps1` | Runs collection, analysis, one consolidated report, and opens it |
| `Invoke-Assessment.ps1 -SelectScope` | Prompts for subscriptions/groups, discovers only selected workspaces, persists scope, collects, and opens one report |
| `Invoke-Assessment.ps1 -SubscriptionIds <id[]> -ResourceGroups <name-or-id[]>` | Same selected scope without prompts; qualified IDs prevent cross-subscription name collisions |
| `Invoke-Assessment.ps1 -Action Reports -RunRoot <selected-run>` | Regenerates using the saved scope without Azure discovery or collection |

For scope changes, behavioral tests must cover multiple subscriptions, same-named
groups, invalid/canceled selections, inaccessible scopes, no workspace results,
SQL approval, and use from both supported working directories. Live validation
must remain within authorized scope; when only one enabled subscription is
available, report multi-subscription validation as mocked rather than live.

## Required evidence

For each command, record:

- Exact command.
- Execution timestamp.
- Exit code.
- Run ID.
- Collector status summary.
- Any partial sources and reason.
- SQL Warehouse state before and after.
- Confirmation that no unexpected Azure or Databricks mutations occurred.

## Failure rule

If any documented command fails:

1. Do not hand it to the user as ready.
2. Fix the root cause.
3. Add a regression test.
4. Rerun the exact command—not a proxy.
5. Update validation evidence and test counts.
